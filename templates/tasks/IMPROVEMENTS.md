# Improvements

What is not a defect but would make the product better: look, clarity, flow, performance,
accessibility, text, code that will get in the way of the next tasks. Each cycle starts with the
planner turning what is here and in `BUGS.md` into tasks.

Who writes here: QA, at the end of each cycle, and the user through `/overclock:feedback`. Who turns
it into tasks: only the planner, marking the line with `→ T###`. **When done, the line is deleted** and
recorded in the log of the step that did it: this file only keeps open improvements.

Priority: `high` (changes the experience a lot; a request from the user is always high), `medium`
(worth doing next cycle), `low` (when there is room; never holds the process).

Format: `- [ ] [priority] <route or file> — <what to change and why> (QA C<N> | user)`
